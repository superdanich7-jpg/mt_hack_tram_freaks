README.md:
# Хакатон МТТЕХ · ИИ-прогноз загрузки трамвайных маршрутов
## Датасет и правила формирования решения

Ваша задача — построить модель, которая прогнозирует **пассажиропоток
(число посадок) на маршрутах трамвая по часам** и формирует файл
`submission.csv` для автоматической проверки.

---

## ⚠️ ГЛАВНОЕ: данных за прогнозируемый период НЕТ

Внимательно прочитайте этот раздел — на нём построена вся задача.

* В архиве вам даны **только 10 месяцев** истории: **январь–октябрь 2025**
  (файлы `train.csv` = январь–август и `test.csv` = сентябрь–октябрь).
* **Данные за ноябрь и декабрь 2025 вам НЕ выдаются и не будут выданы.**
  Именно на эти **два последних месяца** вы должны построить прогноз.
* Валидационный период (**2025-11-01 … 2025-12-31**) — это **прямое
  продолжение временного ряда** обучающего датасета. Вы обязаны определить
  значения посадок **на основе основного датасета** (train + test): недельная
  и суточная сезонность, тренд, праздники, динамика по маршрутам и т.д.
* Проверка выполняется по эталону (`ground_truth`), который сформирован
  организаторами из скрытых данных ноября–декабря и **участникам недоступен**.

> Иначе говоря: это классическая задача прогнозирования временного ряда
> «на 2 месяца вперёд по часам». Вы не сможете «посчитать» ответ из данных —
> его нужно **предсказать**.

---

## 1. Единица прогноза (target)

**Посадка = одна успешная валидация** (`validation_result == 1`).

```
boardings(route, date, hour) = число успешных валидаций на маршруте `route`
                               за календарный час `hour` даты `date`
```

`route` — номер трамвайного маршрута из поля `ngpt_route`
(например, `"25 трамвай"` → `25`).

## 2. Состав архива

| Файл / папка | Описание |
|---|---|
| `train.csv` | Сырые валидации, **январь–август 2025** (обучающая выборка) |
| `test.csv` | Сырые валидации, **сентябрь–октябрь 2025** (тестовая выборка) |
| `test_submission.csv` | **Пример** файла-решения нужного формата (заполнен baseline-прогнозом; метрика < 0.5 — это «пол», который нужно превзойти) |
| `labels/labels_day_train.csv` | Готовая почасовая разметка target по train: `route;date;hour;boardings` |
| `labels/labels_day_test.csv` | То же по test |
| `spravochniki/` | Справочники маршрутов/остановок (координаты) — для карты/веб-сервиса |
| `README.md` | Этот файл |

`labels/*` даны для удобства (это агрегаты `train.csv`/`test.csv` по целевой
величине) — можно обучаться прямо на них.

## 3. Схема сырых CSV (`train.csv`, `test.csv`)

Разделитель `;`, кодировка UTF-8, первая строка — заголовок.

| Колонка | Описание |
|---|---|
| `tran_no` | Номер транзакции (id события) |
| `device_no` | Идентификатор валидатора (устройства) |
| `tran_date_time` | **Дата-время валидации — основной timestamp** |
| `begin_date_time` | Дата-время начала поездки (служебное) |
| `input_date_time` | Дата-время загрузки записи. **Ненадёжно** (местами битые даты) — не использовать |
| `crd_hashcode` | Обезличенный хеш карты (для подсчёта уникальных пассажиров) |
| `validation_result` | Результат валидации; `1` = успех (посадка), прочие коды = отказы |
| `tran_type_id` | Тип транзакции (`52` — основной проход и др.) |
| `place_id` | Код площадки/депо (5–6 значений). **Не остановка** |
| `good_type` | Тип билета/тарифа (`СКМ МГТ`, `КОШЕЛЕК`, `30 дней`, …) |
| `pass_route` | Цепочка пересадок пассажира (сырое, зашумлённое поле) |
| `ngpt_route` | Маршрут НГПТ, напр. `"25 трамвай"`. **Источник `route`** |
| `bus_exit_no` | Номер выхода/графика ТС |
| `garage_number` | Гаражный (бортовой) номер трамвая |

## 4. Маршруты

В данных 10 трамвайных маршрутов: `1, 5, 7, 11, 12, 17, 25, 26, 28, 50`
(маршрут `5` встречается редко). Прогноз ведётся **на уровне маршрут × час**.

> Геопривязка. Справочники в `spravochniki/` дают координаты остановок для
> карты веб-сервиса, но их набор маршрутов пересекается с данными лишь по
> `{1,5,7,11,12}`, а поле `place_id` — это площадки/депо, не остановки.
> Поэтому остановочная детализация — **необязательный бонус**, основная метрика
> считается по маршрут × час.

## 5. Разбиение по датам

| Выборка | Период | Выдаётся | Назначение |
|---|---|---|---|
| train | **2025-01-01 … 2025-08-31** | ✅ да | обучение |
| test | **2025-09-01 … 2025-10-31** | ✅ да | валидация/подбор |
| **прогноз** | **2025-11-01 … 2025-12-31** | ❌ **нет** | **вы строите `submission.csv`** |

## 6. Формат `submission.csv`

Разделитель `;`, UTF-8, заголовок обязателен. Колонки строго:

```
route;date;hour;prediction
```

| Колонка | Тип | Значения |
|---|---|---|
| `route` | int | `1,5,7,11,12,17,25,26,28,50` |
| `date` | `YYYY-MM-DD` | `2025-11-01` … `2025-12-31` |
| `hour` | int | `0`…`23` |
| `prediction` | число ≥ 0 | прогноз числа посадок (округляется к целому) |

Файл должен покрывать **полную сетку** ключей:
`10 маршрутов × 61 день (ноя+дек) × 24 часа = 14 640 строк`.
Проще всего взять `test_submission.csv`, сохранить структуру и заменить столбец
`prediction` вашими прогнозами.

## 7. Метрика

```
WAPE       = Σ|y − ŷ| / Σy
WAPE-score = max(0, 1 − WAPE)      ∈ [0, 1],  больше — лучше
```

где `y` — фактические посадки (скрытый эталон), `ŷ` — ваш прогноз.
Метрика устойчива к нулям (ночные часы) и к разбросу объёмов между
маршрутами/часами. Пример-baseline (`test_submission.csv`) даёт
**≈ 0.48** — его нужно превзойти.

## 8. Особенности данных

1. `input_date_time` местами содержит будущие/битые даты — используйте
   `tran_date_time`.
2. Файлы имеют небольшой суточный «хвост» в следующий месяц; агрегируйте
   строго по дате из `tran_date_time`.
3. `pass_route` — зашумлённое поле цепочки пересадок; для номера маршрута
   используйте `ngpt_route`.
