# WEB_SERVICE.md — требования к веб-сервису

Это часть задания. ML готовит `forecast.csv` — сервис его показывает.

## Роль сервиса

Элемент системы диспетчеризации и оперативного управления трамваями
Москвы.

## Ключевые требования (из Q&A)

- Оперативность: быстро переключаться между представлениями.
- Однозначность считывания: цифровые/буквенные обозначения маршрутов
  читаемы на увеличенном и уменьшенном масштабе.
- Минимум действий, чтобы перейти от общей картины к развёртке
  конкретного маршрута.
- Не терять контекст: всегда видно, с каким объектом работаешь.
- Управляющие элементы — в области действия над объектом.
- Тёмная тема (диспетчеры работают с экранами).
- Сплит-режим: можно менять расположение блоков и переключать
  представления.
- Адаптивность под стандартные экраны диспетчера.
- Базовая авторизация (не обязательно «по всем правилам»).
- Кросс-платформенность.

## Что показывать

- Общая картина дня по всем маршрутам.
- Развёртка по конкретному маршруту: по часам.
- Переключение: день / неделя / месяц.
- Графики загрузки.
- Возможно — карта остановок (по справочникам).
- Прогноз и факт (если есть).

## Стек (рекомендация)

- Backend: FastAPI или Flask.
- Frontend: React / Vue / Svelte — что команда знает.
- Docker + docker-compose.
- Авторизация: basic auth или простой логин.
