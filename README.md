# ИИ-прогноз загрузки трамвайных маршрутов

Хакатон МТТ «ИИ-прогноз загрузки трамвайных маршрутов». Прогноз почасового
пассажиропотока по 9 трамвайным маршрутам Мосметро на горизонте
**ноябрь–декабрь 2025**.

## Текущий результат

**Подтверждённая оценка на платформе хакатона: WAPE-score = 0.88040**
за ноябрь–декабрь 2025. Это лучший результат проекта.

| Метрика | Значение |
|---|---|
| **WAPE-score на платформе (ноябрь–декабрь 2025)** | **0.88040** |
| WAPE-score на отложенном месяце (октябрь 2025) | 0.9038 |
| MAE, пассажиров/час | 90.5 |
| Бенчмарк организаторов (файл-шаблон) | 0.4776 |
| Сабмит | `submissions/submission.csv` — 14 640 строк, валидация 24/24 OK |

Модель: LightGBM (`regression_l1`), **36 признаков, 1959 деревьев**.
Внешние данные: почасовая погода Open-Meteo, календарь праздников РФ,
отопительные градусо-дни, нефть Brent и курс USD/RUB.
Полный разбор — [`reports/december_analysis.md`](reports/december_analysis.md).

### Найденная и исправленная регрессия

Признак `daylight_hours` был добавлен как «открытые данные», но на деле
это монотонная функция `dayofyear` — ровно тот сезонный календарный
признак, который проект осознанно исключил (деревья не умеют
экстраполировать за обучающий диапазон). В ноябре–декабре световой день
выходит **ниже** минимума обучения (7.00 ч против 7.13 ч) для 21 дня из
61, и модель занижала 31% суммы прогноза до 0.63 от октябрьской нормы.

Локальные валидации этого не показывали: на исторических фолдах август–октябрь
световой день ниже минимума обучения не выходит. Теперь в коде есть
регрессионный тест `test_no_feature_leaves_training_range`, который
запрещает любому признаку выходить за обучающий диапазон более чем на
20% дней прогноза. Подробности — [`reports/decisions.md`](reports/decisions.md).

## Быстрый старт

```bash
python -m pip install -r requirements.txt
python -m src.main          # весь пайплайн: данные → обучение → сабмит → проверка
```

Или по шагам:

```bash
python -m src.data                  # -> data/processed/boardings.parquet
python -m src.external.weather      # погода Open-Meteo (нужна для погодных признаков)
python -m src.external.holidays     # календарь праздников РФ
python -m src.external.extra_data   # нефть Brent и курс USD/RUB
python -m src.predict               # -> submissions/submission.csv + forecast.csv
python -m src.validate_submission   # проверка формата (24 условия)
python -m pytest tests -q           # 48 тестов
```

Если `data/external/weather.csv` отсутствует, пайплайн не падает: он
переключается на календарные признаки и пишет предупреждение в лог.

## Главный вывод по модели

Из полного поиска — новые группы признаков, CatBoost, XGBoost,
LSTM+attention, ETS/SARIMAX, Optuna, четыре варианта ансамблирования —
отбор прошли **три** изменения:

1. **cross-route признаки** — профиль города, доля маршрута, тренд уровня;
2. **внешние открытые данные** — отопительные градусо-дни, Brent, USD/RUB;
3. **гиперпараметры Optuna**, подобранные на валидационном фолде 2025-09.

Всё остальное уступало одиночному LightGBM. Числа и обоснования —
в [`reports/final_model_analysis.md`](reports/final_model_analysis.md).

Ключевой методологический момент: решения принимались по среднему на трёх
временных фолдах, а не по лучшему числу на одном месяце, поскольку
разброс между месяцами (≈0.017 WAPE-score) в 2–3 раза больше разницы
между конфигурациями (≈0.005).

## Что проверили и отвергли

- **Физический потолок вместимости вагона.** Ни одно из 14 640 предсказаний
  не превышает исторический максимум (0.0000%), в данных нет следов усечения
  сверху. Обрезка изменила бы ноль строк.
- **Световой день и темнота.** Вызвали падение 0.87597 → 0.83831
  (см. раздел выше).
- **Разложение «уровень + рост»** (`trend`, `trend_lag`, `trend_slope`).
  Улучшает три временных фолда, но на помесячном бэктесте эффект нулевой
  (−0.00002). Оставлено в коде как воспроизводимый эксперимент.
- **Сглаживание прогноза** скользящим окном — резко ухудшает метрику
  (0.906 → 0.107), потому что затирает пики, на которые WAPE чувствителен
  сильнее всего.
- **Ансамбли, CatBoost, XGBoost, нейросеть, ETS/SARIMAX** — все хуже
  одиночного LightGBM на тестовом месяце.

## Область определения и ограничения

- Модель обучена на 9 маршрутах (1, 7, 11, 12, 17, 25, 26, 28, 50);
  `route=5` в сабмите заполняется нулями по условию задачи.
- Горизонт прогноза — до 2 месяцев без доступа к «свежим» данным,
  поэтому сезонные календарные признаки исключены: деревья не умеют
  экстраполировать их за пределы обучающего диапазона. **Это правило
  распространяется и на «открытые» признаки**: любой признак, выходящий
  за границы обучения на целевом горизонте, должен быть удалён — иначе
  модель систематически занижает прогноз (см. историю скора выше).
- Зависимость от внешних данных: Open-Meteo (фактическая погода) и
  календарь праздников РФ. Без погоды модель работает, но хуже.
- Перенос на другие маршруты/периоды потребует переобучения: подбор
  числа деревьев делается через early stopping на отложенном месяце.
