# Дашборд прогноза пассажиропотока трамваев Москвы

Фронтенд хакатон-проекта: **React 19 + TypeScript + Vite**, тёмная тема, сплит-режим экрана,
панель «Внешние факторы». Бэкенда пока нет — **все данные мок**: детерминированный генератор
в `src/data/forecast.ts`.

## Запуск

```bash
cd web/frontend
npm install
npm run dev      # http://localhost:5173
npm run build    # tsc -b && vite build
npm run lint
```

## Возможности

| Требование | Реализация |
| --- | --- |
| Тёмная тема | Токены в `src/index.css`, цвета графиков в `src/lib/palette.ts`, тёмная подложка карты |
| Сплит-режим | `react-resizable-panels` (`Group` / `Panel` / `Separator`): перетаскиваемые разделители между картой, графиком и KPI. Переключатель «Сплит / Только карта / Только графики» в шапке |
| Интерактивная карта | `react-leaflet` (Leaflet 1.9): бесплатные тайлы OpenStreetMap, приведённые к тёмной теме CSS-фильтром `invert(100%) hue-rotate(200deg) brightness(90%) contrast(85%) saturate(80%)` на `.leaflet-tile-pane`; полилинии маршрутов, маркеры остановок (цвет — средняя заполняемость, размер — загрузка), всплывающая карточка остановки |
| График реагирует на выбор остановки | Клик по маркеру или по строке рейтинга обновляет `stopId` фильтра → график, KPI и экспорт пересчитываются |
| Фильтры | 4 dropdown: маршрут, остановка, интервал времени, горизонт прогноза (день / месяц / год) |
| Панель «Внешние факторы» | Переключатель «Выходной / праздничный день», селектор погоды (Ясно / Дождь / Снегопад), ползунок «Уровень пробок» 0–10. Коэффициенты хранятся в состоянии `Dashboard` и сразу применяются генератором — линия прогноза пересчитывается мгновенно |
| График по часам | `recharts` `ComposedChart`: площадь прогноза, линия факта прошлого периода, линия заполняемости по правой оси, отметка пикового часа, кастомный тултип, переключаемая таблица данных |
| Экспорт в CSV | Кнопка в шапке скачивает ровно те строки, что отображаются на графике/в таблице (`buildForecastCsv`); имя файла `tram_forecast_<область>_<горизонт>_<дата>.csv` |

Дополнительно: KPI-карточки (прогноз за интервал и за сутки, пиковый час, точность модели),
рейтинг топ-6 остановок маршрута с быстрым переключением, адаптивная карта
(`ResizeObserver` → `map.invalidateSize()` при перетаскивании разделителей).

## Внешние факторы (корректирующие коэффициенты)

| Фактор | Значения | Влияние |
| --- | --- | --- |
| Выходной / праздничный день | чекбокс (вкл/выкл) | множитель объёма **×0.62** |
| Погода | Ясно / Дождь / Снегопад | множитель объёма **×1.0 / ×1.1 / ×1.2** (в непогоду трамвай привлекательнее) |
| События на маршруте | Штатно / Ремонт дорог / Мероприятие | множитель объёма **×1.0 / ×1.15 / ×1.3** |
| Уровень пробок | ползунок 0…10 | доля сглаживания пиков **0…45 %** (`0.45 × уровень / 10`) |

Как это работает (`src/data/forecast.ts`):

- `externalVolumeMultiplier(factors)` — произведение коэффициентов выходного дня, погоды и событий,
  масштабирует базовый суточный объём остановки;
- `trafficSmoothingRatio(factors)` — «размазывание» пиков: значение часа смешивается со средним
  по суткам (`value + (mean − value) × ratio`), поэтому суточный объём сохраняется, а утренний
  и вечерний пики становятся ниже, ночные впадины — выше;
- `describeExternalFactors(factors)` — готовое описание применённых коэффициентов для чипов в
  панели, футера и колонок CSV (`Множитель объёма (внешние факторы)`, `Сглаживание пиков пробками, %`,
  `Фактор: …`).

Состояние живёт в `Dashboard` (`factors` + `INITIAL_FACTORS`) и прокидывается в `useDashboardData`,
поэтому от факторов зависят все представления: график, KPI, рейтинг остановок, размер/цвет
маркеров на карте и содержимое CSV.

## Как подключать бэкенд

Компоненты ничего не знают о мок-данных: всё идёт через две функции в `src/data/forecast.ts`.

```ts
buildForecast({ routeId, stopId, intervalId, horizonId, factors, generatedAt }): ForecastDataset
buildStopRanking(routeId, horizonId, factors): StopRankingRow[]
```

Достаточно заменить их реализацию на вызовы API, сохранив возвращаемые типы из `src/types.ts` —
`Dashboard`, `ChartPanel`, `MapPanel`, `StatsPanel` и экспорт CSV менять не придётся.
Справочники маршрутов и остановок: `src/data/routes.ts` (`ROUTES`, `STOPS`, `ROUTE_PATHS`).

## Заметки

- Мок-данные детерминированы: PRNG засевается от `hash(остановка|маршрут|горизонт)`, поэтому
  одинаковые фильтры дают одинаковые числа при каждом рендере и в экспорте.
- Подложка карты — бесплатные тайлы OpenStreetMap (`https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png`),
  нужен интернет. Тёмный вид даёт CSS-фильтр на `.leaflet-tile-pane` в `MapPanel.css`;
  атрибуция OSM выведена в правом нижнем углу карты. Для продакшена с большой нагрузкой
  замените `TileLayer` на собственный тайл-сервер (политика OSM запрещает тяжёлый трафик).
- Трассы маршрутов нарисованы отрезками между остановками: это мок-геометрия, а не реальные рельсы.
- CSV собирается с BOM и разделителем `;`, чтобы корректно открываться в Excel с русской локалью.
